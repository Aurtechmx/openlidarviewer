# v0.7.0

v0.7.0 reads ASPRS classes and classification flags from one place, adds two terrain tools, and tightens how units, datums and sampled data are stated. No existing claim changed evidence level: the register holds 38 claims, 17 of them at E4 and none at E5.

ASPRS class semantics now come from one module instead of a table in each of eight places, and names depend on the point data record format the file declares. Class 12 is Overlap Points under the legacy formats and reserved from format 6, where overlap is carried by a flag. Classes 19 to 22 are named rather than reported as user-defined.

Classification flags survive a load. Synthetic, Key-Point, Withheld and Overlap are read from both record layouts, carried on the point model and written back by both LAS writers. Terrain analysis, the volume tools, profiles, density, epoch comparison and feature extraction leave Withheld points out and record how many they excluded.

Terrain Flow Pulse routes flow over a terrain surface and reports depressions. Terrain Access screens a surface for traversability and finds a least-cost route. Both say when the terrain run behind them is a preview or blocked, and neither is a safety or hydrology result.

A layer the loader reduced to a display sample can be exported at full resolution or reloaded at a higher density, and anything written from a sample says so. Measurements and exports state the horizontal and vertical units they use, take each measurement's frame from the scan it was taken on, and refuse geographic, Web Mercator and geocentric frames for distances, and datum shifts the application cannot apply.

Several figures earlier builds reported are corrected. Volume is weighted by area rather than by point, the lasso volume uses the drawn lasso rather than its convex hull, gaps in a footprint are interpolated, stated and graded, and a footprint with no measured points is withheld. A CRS given only as an EPSG code takes its unit from the code instead of assuming metres. On-screen measurements match the exports on mixed-unit scans, change detection thresholds at a propagated level of detection, and measurement GeoJSON is written in WGS 84 longitude and latitude. The clip box now changes what is drawn and picked.

A glTF or GLB that lists Draco mesh compression is refused, because the decoder is not bundled and none is downloaded.

The viewer starts when it is framed by a page on its own origin or by an origin the deployer listed in `OLV_EMBED_ORIGINS` at build time. Any other parent gets a notice and the viewer does not start.

Measurement, navigation, terrain analysis and the exports read each layer's up axis by one rule. A PLY or OBJ under a CRS is treated as Z-up, one with no CRS is read as Y-up for measurement while terrain analysis detects its axis from the point layout, and a glTF or GLB under a CRS has no up axis, so its heights are withheld.

A session restores its coordinate system only when the file records it as one its author confirmed, and a toast names the CRS and its unit.

Two epochs that declare the same horizontal CRS are compared in their supplied coordinates. No registration is estimated, and a horizontal misregistration between them appears as change.

Nothing here is a survey-grade result, and held-out reference validation has not been done.
