# Classifier corpus

The frozen synthetic corpus the derived point classifier
(`olv.class.derived-heuristic`) is measured on, and the record of one run.

## What is here

| Path | What it is |
| --- | --- |
| `results-classifier-corpus.json` | The record: per-class precision, recall and F1 by scene and pooled, plus macro-F1, unclassified rate and false-building rate. Written by `tests/classifierCorpusEval.test.ts`. |

The corpus itself is not stored here. It is generated by
`src/validation/classifierCorpus.ts` from integer seeds, so the scenes are a
function of the source and not a set of committed bytes that could drift from
it. `corpusDigest` folds the whole corpus into one hash, and that hash is pinned
in two places: `CORPUS_DIGEST` in `tests/classifierCorpus.test.ts`, which
recomputes it from a fresh build, and `EXPECTED_CORPUS.digest` in
`scripts/verify-classifier-corpus.mjs`, which compares it against the record.

## How to refresh and check it

```
npx vitest run tests/classifierCorpusEval.test.ts   # recompute the record
npm run validation:classifier-corpus:verify         # gate it
```

The test is the recompute; the script is the gate. The script does not run the
classifier, so a pass means nothing until the record has been refreshed.

## What the numbers are, and are not

Every scene and every label was generated by this project. The result is one
implementation measured against a generator the same project wrote: synthetic
evidence about where the rules break and by how much. It is not field
validation, it is not survey truth, and it does not describe accuracy on a real
scan. Returns are uniform-random in plan with no sensor geometry, no scan
pattern and no range noise, and the objects are boxes and clumps of points.

Two scenes score badly and stay in the record: `rolling-terrain` at 0.40 ground
recall and 0.28 macro-F1, and `walls-roofs` at 0.33 macro-F1. `steep-terrain`
sits at 0.64 ground recall. The gate refuses a drop below those figures; it does
not call them good. The diagnosis, and what changed in classifier v2, is in
`docs/validation/classifier-corpus-eval.md`.
