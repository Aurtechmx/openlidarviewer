# Reproducibility: OpenLiDARViewer v0.6.3

The version-agnostic toolchain, pinning, and method are in [REPRODUCIBILITY.md](../../REPRODUCIBILITY.md). This note fixes the figures reported for this release to the commands that produce them, so a reviewer can regenerate each rather than take it on trust.

## Toolchain

- Node.js ≥ 22 (CI uses 22); dependencies pinned by `package-lock.json`.
- Install from a clean clone with `npm ci` (not `npm install`).

## Running the gate

```
npm run gate          # the whole battery, then a literal "GATE EXIT: <code>"
npm run test:release:tag   # the gate plus the full Playwright suite; run before tagging
```

`npm run gate` is the only command whose result should be quoted. It writes
`release/gate.log`, prints its own exit status, and regenerates
`docs/validation/test-evidence.json` from that log, but only when the run
passed, so a failing gate cannot refresh the figures it failed to earn.

Every test count in these documents is read out of that evidence file and
checked by `npm run lint:evidence`. Do not type the numbers in. The check is
not ceremonial: removing one test file during the v0.6.0 cycle moved the terrain
bucket by a single test, the documents still said the old figure, and this is
what caught it.

Take the exit status from the `GATE EXIT:` line, not from the last lines of
output. Piping the gate into `tee` or `tail` reports the exit code of `tee`,
which is essentially always 0, and the summary above it can read entirely green
while the run failed.

## Canonical toolchain

Every published figure is produced on one pinned toolchain. Reproducing on a
different runtime is fine and useful, but it is not the canonical record.

```
Node  22.17.1   (the 22.x build that ships the pinned npm)
npm   10.9.2    (package.json `packageManager`)
```

```bash
git checkout v0.6.3
nvm use                 # reads .nvmrc
npm ci
git diff --exit-code -- package-lock.json   # a clean install must not rewrite it
npm run gate                                 # require the literal GATE EXIT: 0
```

The development toolchain moved to TypeScript 7.0.2, Vite 8.1.5 and Playwright 1.62.0 in this release. TypeScript 7 is the native compiler and a major version, so the typecheck, all five test buckets and both builds were re-run against it. Application source did not change. All three packages are development-only, so the runtime dependency set and the SBOM are untouched.

## Two kinds of evidence, and which one to cite

| Record | Where | Authoritative? |
|---|---|---|
| `docs/validation/test-evidence.json` | committed in the repo | **No**. `releaseAuthoritative: false`, a development run |
| `test-evidence-v0.6.3.json` | attached to the release | **Yes**. Generated by the exact-tag run |

Evidence is collected FROM a gate run, so committing it creates a new commit and the committed record always describes the commit before the one it ships in. The release workflow avoids that entirely by generating the record as an artifact of the tagged checkout rather than committing it.

Cite the attached file.

## The two-platform reproducibility result

The tracked result is at `docs/validation/evidence/portability-v0.6.2/`:
`status: reproduced`, platforms darwin-arm64 and linux-x64, from one workflow
run at one commit. The seeded source cloud hashes identically on both, then 15
artifact hashes and 18 scalars are compared at a tolerance of exactly zero, and
none differ. Host, timing and build-identity fields differ and are published per
platform rather than pooled.

Reproducing it needs both legs. `benchmark:repro:portable` on one machine
produces one leg; `benchmark:compare-platforms` needs two leg directories and
reports `single-platform` with `claimEstablished: false` when it has one. That
verdict is correct for one machine and is not the verdict of the tracked
evidence.

Scope: two little-endian platforms, one commit, one synthetic seeded fixture.
Windows is untested, no big-endian host has run a leg, and no real scan data is
in the comparison.

## The v0.6.1 suite baseline

`VALIDATION_REPORT_v0.6.3.md` states that all eighteen defects fixed here were
missed by the test suite as it stood at v0.6.1. To reproduce that run:

```bash
git worktree add /tmp/olv-v061 v0.6.1
ln -s "$PWD/node_modules" /tmp/olv-v061/node_modules
cd /tmp/olv-v061 && npx vitest run
```

It exits 0. The measured result, recorded in
`validation/defects/defect-registry.json` under `conventionalSuiteDefinition`,
is 507 test files passing and 2 skipped, and 6,182 tests passing and 16 skipped.
A green run there means the suite passed while the defective code was present.
It is not evidence that any test in it exercised a defect.

One record is marked `mixed` rather than `green`: `benchmarks/runner/verify.ts`
did not exist at v0.6.1, so the v0.6.1 suite cannot be evaluated against the two
verifier blind spots in it.

## Environment notes

- The `slow` bucket spins up the WASM LAZ decoder; the runner caps workers at 2 and raises the per-test timeout for it.
- Four e2e specs skip when the optional autzen COPC fixture is not on disk. That is a conditional skip, not a failure.
- The e2e suite is split into two Playwright projects. `deterministic` blocks; `gpu` (specs tagged `@gpu`) is advisory because its result depends on the WebGPU adapter a runner exposes. An untagged spec lands in the blocking project.
- `npm run coverage` excludes `tests/terrainRunnerDensityWiring.test.ts`. Under v8 instrumentation each of its cases takes about 75 s. It still runs in the release buckets, so nothing goes unexercised; only the coverage measurement omits it.
- Coverage is a blocking stage of the release-mode gate and its output ships inside `gate.log`. Mutation is deferred to a scheduled workflow, and the record cites that run rather than executing it at tag time. Ordinary branch CI runs neither, so between releases treat the figures as reproducible measurements rather than preserved evidence.
- `benchmark:backends` records a requested backend that fell back as backend-unavailable rather than substituting the one that ran. In Node, with no WebGPU adapter, the GPU leg is unavailable and the browser leg carries it.
- `benchmark:clean-clone` records itself as unrun, not failed, when it is executed inside an extracted archive with no repository around it.
- Browser-observable behaviour (streaming visuals, GPU paths) is exercised by the e2e suite; a green GitHub Actions run on the tagged commit is the gating browser evidence for publication.
