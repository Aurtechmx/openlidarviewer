# v0.6.9 GUI declutter and guidance: what the tree supports

Date: 2026-09-13
Status: design; the bounded set below is implemented, the rest is decided here
Source: an external 59-section shell-and-guidance prompt. Every factual claim
in it was verified against the tree by eight read-only passes before any of it
was accepted. Corrections are recorded so the next reader does not re-derive
them.

## The constraint that decides most of it

The live entry chunk measures 806 KiB against an 812 KiB ceiling
(`scripts/check-bundle-budget.mjs:32`). Every past raise is a recorded human
decision, and the rule set at the 768 step forbids a ceiling equal to the live
number. `src/main.ts` sits exactly on its shrink-only monolith baseline (5557
lines, `docs/validation/monolith-size-baseline.json`), so one added wiring
line fails `lint:monolith-size`; its fan-out is held shrink-only at 118 runtime
edges by `lint:module-graph`. CSS is not budgeted.

Measured transfer function (`docs/performance.md:70-118`, `bundle-stats.html`):
a UI module costs roughly 0.6-0.9× its source bytes in the live chunk. Past
shell surfaces: the DesktopWorkspace rail cost ~4 KiB live and only because it
re-parented panels; the Speed-to-Quality control cost 13 KiB with its popover
already lazy; a lazy panel whose only eager part is its entry control cost
2 KiB. The prompt's Phase 1 set, taken eagerly (Activity Rail, top bar,
compact navigation, status bar, drawer policy) plus its Phase 4 guidance
engine and Phase 5 density mode, sums to roughly 25-50 KiB. That is four to
seven times the room, before the monolith ratchet is reached.

Phases 1, 4 (engine) and 5 (density mode) are therefore not implementable under
the standing rule against raising ceilings. They are decisions, listed at the
end with their measured cost.

## Corrections to the source prompt

1. §3 "persistent bottom tool dock". It is bottom-left (`45-dock-and-panels.css:3`)
   and hides on the empty state (`toolDock.ts:350`). The bottom-centre slot is
   the nav HUD; the two were separated to stop click-stealing.
2. §5 "large persistent navigation HUD". Already dismissible and persisted
   (`olv.nav.helpPinned`, `NavBar.ts:142`), capped at 360 px
   (`50-navigation-bar.css:261`), and yields during drags. The presets
   "Top/Front/Side/Iso" do not exist: Camera is Top/Iso/Oblique/Planar, Views
   is Top/Bottom/Front/Back/Left/Right. Plan and Ortho are two chips;
   Perspective is Ortho-off.
3. §8 laptop coexistence. No laptop breakpoint exists anywhere in
   `src/styles/`; the only layout threshold is `MOBILE_LAYOUT_QUERY`
   (`isMobileDevice.ts:35`). No width-keyed "opening one closes another" rule
   exists. A 768-1099 px coarse-pointer tablet gets the full desktop layout.
4. §9 "streaming diagnostics among dataset properties". `StreamingPanel` is a
   sibling of the Inspector in the right rail (`main.ts:3623`), never inside it.
5. §10 Appearance panel. "RGB↔Geometry blend" has zero hits in `src/`.
   "Lighting azimuth/elevation/ambient" exists only as hillshade raster
   parameters. The quality selector is a five-stop slider already in the header
   (`qualityPolicy.ts:150`); moving it into a panel is a regression. Visuals
   Studio already exists with the Advanced disclosure (`Inspector.ts:1203`).
6. §11 Analyse. Process Studio already renders product rows with
   Ready/Review/Blocked (`ProcessStudioPanel.ts:52-60, 181-209`). "Slope" is a
   derived-layer type, not a product. Hover-explains-reason was rejected on
   record (`ProcessStudioPanel.ts:171-175`): the reason is a visible caption.
7. §17/§32 evidence codes. No raw `E<n>` reaches any UI module; the badge
   vocabulary is plain words (`evidenceLevel.ts:80-93`).
8. §13/§14 Profile. A bottom dock with drag, collapse and persisted height
   already exists (`profileWorkbenchDock.ts`, key
   `olv:measure:profile:workbenchDock:v1`).
9. §28 hover values. Measurement values are permanent labels with
   collision-avoidance (`MeasureController.ts:1966-2001`, `MeasureOverlay.ts:222`).
   Revealing them on hover removes information the user has now.
10. §15 status bar. A persistent coordinate readout with honest unit and frame
    status already exists (`coordinateHud.ts`, "local frame" / "frame
    unresolved"); the backend pill and streaming headline exist. What does not
    exist is one strip holding all three.
11. §21/§29 layer rows. No hover-reveal and no layout shift today; all actions
    are always visible (`40-inspector.css:125-147`). No overflow menu exists.
12. §23 tooltips. There is no tooltip controller anywhere: ~191 native `title`
    sites across 38 files, one styled CSS tooltip scoped to the measure bar that
    `display:none`s on touch, 95 `.disabled =` sites with 3 `aria-disabled`.
    The adoption point exists: `el()` in `ui/dom.ts` already owns `title` and
    `tip` for every module.
13. §36/§50. The palette has zero ARIA (no combobox/listbox/option/
    `aria-activedescendant`); the dock is a bare `div`. Everything else the
    section asks for is in place: forced-colors sheet, 87 `:focus-visible`
    rules, 44 pt targets, 100% `aria-label` on dock and nav HUD.
14. §52. 22 reduced-motion blocks exist. Three gaps: the phone sheet transition
    (`96-phone-sheet-story.css:34`), the mobile dock tool transitions
    (`99-mobile-gui-refresh.css:81`), and `NavController.tweenTo`, so
    frame-all and presets always run a 0.8-0.9 s sweep.

## Applied in this change

Each is absent today, costs no eager bytes or under 100, touches no line of
`src/main.ts`, and changes no analytical value.

- Command palette accessibility: `combobox` input with `aria-expanded`,
  `aria-controls`, `aria-autocomplete`, `aria-activedescendant`; `listbox`
  list; `option` rows with stable ids and `aria-selected`. Lazy chunk.
- `role="toolbar"` with a name on the tool dock, so it is announced as one
  arrow-navigable group.
- Process Studio badges carry a glyph beside the word (✓ ⚠ ✕), the same table
  `readinessEngine.ts:108` uses in the Analyse list. CSS `::before`, decorative.
- Reduced motion on the phone sheet, the mobile dock tools and the camera
  tween: a user who asked for less motion gets a snap, not a sweep.
- `98-layer-health.css:35` used `max-width: 768px` where every sibling uses
  767, overlapping the three `min-width: 768px` desktop rules at one width.
- Measurement handles show a faint fill on hover; today `.olv-m-handle` is
  transparent and the only cue is the cursor.
- The bottom-right corner grip used `ew-resize` for a diagonal resize.
- Two stale comments: `NavBar.ts:231` calls the legend "a 640px panel" against
  a 360 px cap; `actionDefinitions.ts:298` says the recorder flag is "currently
  false" while `WorkflowController.ts:69` sets it true.

## Bounded, not applied here

- Palette rows with a disabled reason. `Action` has no `enabled` field; the
  information already exists in `ProcessService` / `toolPreflight` but the
  registry is eager and built in `main.ts:1725`.
- Eight commonly-cited commands are unregistered: clear streaming cache,
  export contours, reset elevation filter, open Process Studio, and the whole
  nav-mode family. Workspace-mode actions would fix reachability with four
  rows. Every row is eager registry bytes and the handlers need wiring in
  `main.ts`.
- Process Studio is eager (`main.ts:80`, `processStudioMount.ts:29`) although
  tab-gated, unlike the palette, context menu and QualityPanel. Deferring it
  follows `130a92ac` and `980bee28` and reclaims headroom rather than spending
  it; it is the one item that makes room for the others.
- `--hover` / `--selected` / `--editing` tokens. `--accent` appears 275 times
  carrying hover, selected, active and focus at once. A token split is a
  stylesheet-wide pass.
- Eight hard-coded 8-10 px sizes below the 11 px token floor, all in mobile
  chrome. The recorded debt is a re-typing pass.
- Guidance strip for Inspect, Annotate, Probe, Clip and Lasso; only Measure
  has one (`MeasureController.ts:642`), and four uncoordinated banners can
  coexist.
- Measurements have no selection concept at all; "selected" needs state in
  `MeasureController` and `MeasurePanel`, not CSS.

## Decisions for the maintainer, with measured cost

| Surface | Eager cost | Also needs |
|---|---|---|
| Shared tooltip/guidance engine | 3-6 KiB, strings inflate hardest under the live transform | ~191 call sites converted through `el()` |
| Activity Rail replacing the dock | 4-8 KiB if it re-parents; more if it adds chrome | Snapshot, Copy view link and Close dataset relocated (dock is their only home) |
| Status bar strip | 2-4 KiB with popovers lazy | `main.ts` wiring lines |
| Compact navigation control | net favourable only if it replaces the NavBar (~19-28 KiB live) | camera logic untouched |
| Focused/Advanced density mode | 13 KiB by the Speed-to-Quality precedent | policy, persisted preference, boot-time apply |
| Pinnable Context Panel host | 2-3 KiB with the body lazy | Scene mode first |
| Laptop drawer exclusivity | 1-2 KiB | a breakpoint that does not exist |
| First-use hints | under 1 KiB, and only if lazy like the tour | persistence key |

Any two of these together exceed the headroom. A ceiling raise sized for more
than one branch in flight, a hand-edited monolith baseline, and the
decomposition that moves wiring out of `main.ts` are the three decisions the
codebase asks for before Phase 1 can start.
