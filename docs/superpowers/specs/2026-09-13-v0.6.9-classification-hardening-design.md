# v0.6.9 automatic classification: what the tree supports

Date: 2026-09-13
Status: design; the bounded set below is implemented, the method change is decided here
Source: an external 48-section classification-hardening prompt. Corrections to
it are recorded below.

## What ships today

`olv.class.derived-heuristic@3` (`src/render/class/deriveClassification.ts`,
registered at `src/science/methodRegistry.ts:81-97`). Eleven pipeline stages and
one sequential cascade: grid minimum with a second-lowest per cell, a one-pass
neighbour-median despike, 24-pass hole fill with a global-mean floor, a
progressive morphological opening on the grid over a geometric window ladder
(five stages at the default 20 m object size), bilinear DTM, HAG clamped at
zero, 3×3 pooled roughness, an RGB excess-green cue, a multi-return cue, and a
wall rescue that is the only consumer of the eigen descriptors. Preset digests
bind id, integer version and the frozen numeric parameters
(`deriveClassification.ts:391-397`).

The prompt's "current" diagram (point → heuristic rule → class) is accurate.

## Corrections to the source prompt

1. The classifier does not use the registry's ground filter. `olv.ground.smrf@1`
   (`src/terrain/ground/groundFilter.ts`) serves the terrain and change paths;
   the classifier carries its own inline morphology at
   `deriveClassification.ts:748-805`. Two implementations, two threshold models.
2. Abstention already exists: class 1 on ground support below 0.5 and on a
   planar building candidate below 0.66 support (`:981-986`, `:1013-1018`),
   plus a whole-run refusal on degenerate geometry. What does not exist is a
   per-class score, a runner-up or a margin.
3. `ClassificationEvidence` (`src/classification/classificationEvidence.ts`)
   exists with `runnerUpSupport`, `flags.conflicting` and `isReviewUncertain`.
   Its only constructors are tests. It is staged, not wired.
4. The full eigen descriptor set (linearity, planarity, sphericity,
   omnivariance, anisotropy, eigenentropy, surface variation, verticality) is
   implemented and tested in `src/classification/geometryDescriptors.ts`. The
   classifier reads one bit of it, `planar-vertical`, on the residue of tall,
   supported, non-green, single-return points the roughness rule rejected. No
   descriptor is evaluated at more than one radius; the module header's
   "multi-scale" is unbacked.
5. Determinism holds: no RNG, snapshot-guarded passes, a rerun test and a
   permuted-order test (`tests/invariantClassification.test.ts:353-381`).
   Translation and rotation invariance are bounded and documented as float32
   grid-flooring artefacts, not violated silently.
6. The unit handling is fail-open. `classifierFrame.ts:68-86` substitutes 1 for
   an unknown linear unit and runs metre thresholds against source units; the
   preflight rates the product `review` / `UNIT_UNKNOWN`, the run output says
   nothing about the assumption.
7. Classes 7 and 18 are never assigned; the emitted set is 1 to 6. A low blunder is
   removed from the seed surface but the point itself becomes Ground, because
   `hag = max(0, h)` (`:853-854`). `tests/classifierGroundRecallDiagnosis.test.ts:182`
   pins this as a known gap rather than hiding it.
8. No second ground hypothesis exists in any form: not TIN, not CSF, not a
   staged stub. The `GroundClassifierFn` seam in `trainOnlyReclassify.ts:60`
   could host one; nothing implements it.
9. NIR is undecoded on all four decode paths (`lasDecodeShared.ts:70-78`,
   `copcChunkDecode.ts:126`, `eptLaszipDecode.ts:149`, `lazChunkWorker`). Scan
   angle, scanner channel, edge of flight and the classification flag bits are
   never read. The classifier ignores `gpsTime` and `pointSourceId`, which it
   already has.
10. There is no claim register entry for `olv.class.derived-heuristic`. The
    mountain F1 near 0.5 and dense-canopy precision near 0.34 (OpenGF and
    producer class 2) live in a disclaimer on the GROUND-FILTER claim
    (`claim-register.yaml:452`) and a doc-comment table
    (`tests/groundFilterProducerAgreement.test.ts:52-70`). Nothing gates them.
11. `scripts/verify-classifier-corpus.mjs` never reads the record's method id or
    preset digest. A record regenerated under a new version would be compared
    to the v3 baseline and inherit it. The prompt's rule that no evidence may
    migrate to a new method is not enforced by the gate.
12. The run provenance (`ClassifierProvenance`: method tag, preset id, digest,
    parameters, cues) is assembled at `deriveClassification.ts:1134-1147` and
    dropped. `classifierProcessingOp()` exists to chain it into the session
    manifest; its one caller is a test. A derived classification reaches a LAS
    file with no provenance, and an abstention is byte-identical to a
    producer's class 1.
13. The worker path has no point cap. `MAX_FALLBACK_POINTS = 6_000_000` guards
    only the main-thread fallback; the worker receives `cloud.pointCount`
    unbounded and builds a string-keyed `Map` spatial hash with no memory
    probe. Cancellation never terminates the worker; the UI passes no signal.
14. "Confidence 74%" (`ClassLegendPanel.ts:339`, `main.ts:1523`,
    `scanStory.ts:252`) formats a product of three ad-hoc multipliers as a
    percentage. The code comment is candid; the string is not.

## Why the method change is deferred

Sections 4 to 9 and 11 to 13 of the prompt (adaptive terrain threshold, multi-candidate
seeds, noise classes, multi-scale geometry, structure-aware neighbourhoods,
per-class evidence, class-specific thresholds, a second ground hypothesis) all
move numbers. Under this repo's rule a numerical change to a registered method
is a new method id, a full validation re-run, regenerated frozen metrics and a
register entry. The classifier corpus is twelve synthetic scenes; real-scene
validation exists for ALS only (Jemez, Rogue, OpenGF, Estonia) and none of it
is gated; UAV, TLS, MLS and cross-sensor have no validation, real or synthetic.
A v4 promoted against that evidence would be promoted on sophistication, which
the prompt's own §43 forbids. The honest order is: gate what exists, close the
provenance and fail-open gaps, then build v4 as experimental behind its own id.

## Applied in this change

Each is non-numerical: no class code moves on any input.

- An unknown linear unit is named in the run. `classifierParamsForFrame`
  reports when it substituted 1, the run carries a warning and a provenance
  cue, and the run confidence is capped, so a dimensionless run cannot present
  as a metre-calibrated one.
- Run confidence is presented as support, not a percentage: "support 0.74" in
  the legend caption, the toast and the export-health row.

## Bounded, not applied here

- Wire `classifierProcessingOp` into the session manifest and stamp the
  derived provenance into LAS exports (an ExtraBytes or VLR design; distinguishes
  abstention from producer class 1). Touches `main.ts`, held by the monolith
  ratchet until #933 lands.
- Pass an `AbortSignal` from the UI and terminate the worker on abort.
- A claim register entry for `olv.class.derived-heuristic` at E3, with the
  real-scene figures under `scope.unsupported`, and a `methodId` +
  `presetDigest` equality check in `verify-classifier-corpus.mjs`.
- A frozen, gated artefact for the real-scene numbers (`gf-strata` schema
  exists; needs a verify script and baseline).
- Per-class IoU, macro-IoU, named ground Type I/II, abstention rate and coverage
  in the frozen baseline: computable from stored TP/FP/FN.
- Wire `ClassificationEvidence` as a read-only surface over the existing
  support values; a per-point support colour mode (the `confidence` mode today
  colours terrain cells, not classification).
- Tests for scarp/cliff, depression/ditch, low wall near terrain, isolated high
  noise: none exist.

## Decisions for the maintainer

| Item | Cost | Needs |
|---|---|---|
| v4 selective classifier (§4 to §13) | large | new method id, corpus and real-scene re-run, register entry, promotion criteria |
| NIR decode + NDVI (§15) | medium | four decoders, a `PointCloud` field, 16-bit preservation |
| Scan angle / flags decode (§16) | medium | decoder, model, writer round trip |
| Second ground hypothesis (§13) | medium | an implementation behind `GroundClassifierFn`; disagreement is not evidence until validated |
| Domain / OOD preflight (§17 to §18) | medium | the signals exist in `scanFitness` / `datasetIntelligence`; none reach the classifier |
| Worker point ceiling and memory budget (§33) | medium | a measured memory model; a bare cap would refuse clouds the worker handles today |
| Real-world validation matrix (§22) | needs data | UAV, TLS, MLS, cross-sensor have nothing |

## Not in scope

§35 to §37 (neural verifier and governance): nothing to evaluate. §8 structure-aware
neighbourhoods, §21 risk-coverage, §27 per-domain confusion: all require the
per-class score vector that does not exist.
