# v0.6.9: publishability of the evidence gate

Companion to `plan.md`. Sources an external implementation prompt dated
2026-09-13, every claim of which was verified against the tree before being
accepted. Corrections to that prompt are recorded here so the next reader does
not re-derive them.

## Corrections to the source prompt

1. Coverage is NOT absent from the permit chain. `resident-only` reaches it
   through `terrainAnalysisRunner.ts:663` (`streaming: coverageMode ===
   'resident-only'`). Only `sampled` is blind.
2. `coverageMode: 'sampled'` is never assigned in production. The sole non-full
   assignment is `analyseContours.ts:1174`; every producer hardcodes `'full'`
   (`groundFilter.ts:531,639,872`). Three parallel coverage vocabularies exist:
   `Coverage` (`ProcessPlan.ts:29`), `TerrainCoverageMode`
   (`TerrainContracts.ts:108`), and a looser union (`DerivedLayer.ts:38`), and
   the Process Studio one never crosses into terrain or export.
3. The workspace claim file is `src/ui/contourStudioWorkspace.ts`, not
   `src/terrain/contourStudio/`.
4. A01-A20 are not byte-frozen. No digest, lint or hash exists. The freeze is a
   membership test plus two EXACT-COUNT assertions in
   `tests/authorizationMutationBenchmark.test.ts:84-95`: controls === 2 and
   staleCase === 6. Appending a control or a stale case breaks the suite.
5. There is no benchmark generator script. Artifacts are written by an
   env-gated side effect: `GEN_AUTH_ARTIFACTS=1 npx vitest run
   tests/authorizationMutationBenchmark.test.ts`. `benchmarkVersion` is a local
   const in that test, uncoupled from the case list.
6. The benchmark has FOUR metrics. ATR (traceability, target 1) was omitted from
   the prompt's list. UOAR 0, ORR 0, ATR 1, SAAR 0 today.
7. The benchmark→production import direction is allowed. `unreachable-modules`
   pins the benchmark as validation-only, which constrains what may reach IT, not
   what it may read; `crossCheck.ts:23` already imports `../process/numerics`.

## The work

### A. Reason strings that name the wrong fact

Smallest change, highest honesty return, and no test pins any of the prose
verbatim, only reason codes and action ids.

- `processCapabilities.ts:170,187` say "Only the resident STREAMING set is
  loaded" and fire for a static file read with a stride, because
  `isFullCoverage` (`:83`) rejects `'sampled'` identically to `'resident-only'`.
  A static LAS with stride > 1 becomes `{kind:'static', coverage:'sampled'}`
  (`processStudioMount.ts:174-176,212`) and is told it is streaming. Split the
  code: keep `RESIDENT_ONLY` for streaming, add `SAMPLED` for a static display
  sample naming the counts. The vocabulary already exists at
  `toolPreflight.ts:362-367` (`SAMPLED_COVERAGE` vs `STREAMING_RESIDENT_ONLY`)
  and the product path simply does not use it.
- `processCapabilities.ts:217` has the same defect for footprints. The prompt
  missed this one.
- `contourStudioLaunchState.ts:111` says "The current CRS is geographic" and
  fires on `!crsProjected`, which covers `local`, `unknown` and no-CRS-at-all
  (`CoordinateTypes.ts:34`). A scan declaring no CRS is told its CRS is
  geographic. Split `geographicCrs` from `noCrs`.
- `toolPreflight.ts:208` offers "Wait for full visible coverage" for a strided
  static load, where waiting can never complete the read. Offer the reload path.

Tests that move (codes and action ids, not prose):
`processPlanCounterfactualMatrix.test.ts:59-63`,
`processCapabilities.test.ts:98-102,209-214,316-320`,
`toolPreflight.test.ts:203-213,220-222`,
`contourStudioLaunchState.test.ts:94-100` (the one prose test, matches
`/geographic/i`), `processStudioSampledCoverage.test.ts:50-57` (a source-regex
test over `processStudioMount.ts`; brittle, check it before editing that file).

### B. One resolver behind the interface claim and the export stamp

`contourReviewSummary.ts:300-314` and `contourStudioWorkspace.ts:120-129`
(`ladderClaim`) both derive the claim from `launch.status` alone. The permit
continues to `evidenceStatus(governingClaim(...))`. Both start from the same
frame facts (`contourStudioMount.ts:75,112-118`), so today the interface reads
"Supported (internal validation only)" while the file carries EXPLORATORY and
the caveat "The product has not reached its required evidence level."

A second divergence on the same path: a refused `PrecisionPermit` hard-blocks
the export (`exportManifest.ts:149`) while the launch state, having no precision
term, still renders "Supported".

Fix: compute both surfaces from the permit. Render its caveats as the rationale.

### C. Permit and provenance constituent sets

The permit reads `SCIENTIFIC_EXPORTERS[...].claimIds`
(`exportManifest.ts:67-82`); provenance reads `contourArtifactClaims(result)`
(`exportProvenance.ts:607-614`), which picks CONTOURS vs CONTOURS-CARTOGRAPHIC
from the style that actually ran and appends HOLDOUT-RMSE when an RMSEz prints.

Concrete divergence: a crisp-style map PDF. `exporterIdForContourProduct`
(`contourExportPermit.ts:116`) maps every `pdf` to `contour.pdf`, whose claimIds
are `[CONTOURS-CARTOGRAPHIC, DTM]` → governing claim CONTOURS-CARTOGRAPHIC, E2.
The same sheet's provenance resolves `[CONTOURS, DTM]` → DTM, E4. Authorized on
E2, described on E4. Reachable: `contourExportIntent.ts:119-127` sets
`shapeStyle: 'crisp'` whenever tolerance is 0.

Only `pdf`, `dxf`, `svg` and `complete-package` can diverge; GeoJSON splits on
geometry (`contourExportPermit.ts:122`) and DEM ties under the governing rule.

No test compares the two lists. The comment at `exportManifest.ts:51-54`
("authorization and provenance can never disagree") is true of the composition
rule and false of its inputs.

### D. Coverage in the production permit, and the precision fail-open

Two defects of one class: `resolveExportDecision` treats absent evidence as
passing evidence.

- Coverage: `ExportDecisionContext` (`exportManifest.ts:93-114`) has five fields
  and no coverage term. Adding one requires the terrain path to be able to
  express `sampled` at all (correction 2).
- Precision: `inMemoryPrecision.ts:436` returns `{ok:true}` when
  `step === undefined` exactly as when `step <= budget`, and
  `exportManifest.ts:149` refuses only a measured failure. So a scan blocked for
  insufficient precision becomes an authorized exploratory export once its CRS
  is removed. Make the permit three-valued: ok / refused / unmeasured, with
  unmeasured blocking a metric deliverable.

Both want the same regression: with `evidenceStatusOf` stubbed to `'validated'`,
a degraded input must still cap the permit. Every existing unit-downgrade case
passes `precision: null`, so this interaction is currently unexercised.

### E. Analysed basis in the stamp

`ExportProvenanceOptions` (`exportProvenance.ts:337-418`) carries no
analysed/declared counts, no coverage, no stride. `coverageMode`
(`:234`, set `:462`) is a bare string meaning grid extent, and the codebase says
so in four places (`scanFitness.ts:99-103`, `AnalysePanel.ts:3338-3341`,
`analyseContours.ts:1166-1168`). Sampling is disclosed only through a
density-scaling warning (`analyseContours.ts:1287`) that reaches GeoJSON, the
DEM README, the report and the deliverable JSON, but NOT the DXF or SVG text
stamps, which carry no warnings at all (`exportProvenance.ts:877-1004`).

The Terrain report does print `Ground points` / `Used in DTM`
(`terrainReportContent.ts:340-341`), both sample-scoped; neither is the declared
file total.

### F. Benchmark extension

Implementable, with the four corrections above. Before appending: relax the
exact-count assertions to be computed rather than literal, or the first new
control case fails the suite. `CaseOutcome` (`authorizationBenchmark.ts:49-56`)
is modelled on a capability token (`authorized` / `authentic` /
`provenanceResolvable`) and needs a mapping for a permit decision, which has no
token to be authentic about.

## What shipped (branch `feat/authorization-backbone`)

Sections B, C, E and F above are implemented. D's coverage half landed with
the capability conjunct. D's precision half stays open: with the unit
conjunct and the freshness rule an unmeasured precision can no longer reach
`validated`, and refusing the exploratory export as well would make
review-grade work unreachable on any scan without a CRS.

- `src/export/workspaceClaim.ts`: `resolveWorkspaceClaim(frame)` mints the
  complete-package permit and maps its status to the one label the review
  Evidence row and the ladder Claim line print, with the permit caveats as
  the rationale. Under the real register the label is "Exploratory" for
  every scan today (`tests/contourStudioWorkspaceClaim.test.ts`).
- `resolveExportDecision` governs over the exporter's registered ids plus the
  artifact's (`contourArtifactClaims` / `dtmArtifactClaims`) and returns that
  union on the permit as `claimIds` (`tests/permitProvenanceAgreement.test.ts`).
  The registry is not a subset of the artifact set for `contour.package`
  (it lists both geometries; the artifact carries one), so the assertion is
  registry ⊆ permit set and artifact ⊆ permit set. `HOLDOUT-RMSE` was already
  registered.
- `validated` requires an authorization token that verifies authentic, for the
  product, and minted on the current scientific state; otherwise the decision
  is exploratory with "Authorization is stale or absent for the current
  scientific state." The runner hands the frame an authorizer bound to the
  live facts (`tests/exportAuthorizationFreshness.test.ts`).
- `analysedBasis` on the provenance record and `gridExtent` beside the
  deprecated `coverageMode` alias; one sentence printed by the text stamp,
  the JSON, the DEM README, the report and the map sheet
  (`src/terrain/export/analysedBasis.ts`, `tests/analysedBasisStamp.test.ts`).
  The stride is stated only when the counts resolve a whole number; the
  Coconino display sample (15,604,926 / 2,860,558 = 5.455) prints without one.
- Benchmark A21 to A28 and CPAR, `benchmarkVersion` 4, A01 to A20 results unchanged.
  For a permit case "authorized" means the permit resolved `validated`; A25
  also counts a governing-claim disagreement as authorized above evidence;
  A27 counts as authorized only when all six frames agree.

The rank invariant and idempotence the prompt asked for as
`authorizationBackboneInvariant.test.ts` live in
`tests/exportPermitCapabilityConjunct.test.ts`.
