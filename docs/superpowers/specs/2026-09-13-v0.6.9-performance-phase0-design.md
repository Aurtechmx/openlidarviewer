# v0.6.9 performance and UX: Phase 0 scope

Date: 2026-09-13
Status: design, not implemented
Source: an external 38-section implementation prompt. Every factual claim in it
was verified against the tree before being accepted. Corrections are recorded
here so the next reader does not re-derive them.

## Why the scope stops at a baseline

The prompt's own §33 defines seven phases and §2 requires a measured baseline
before any production change. Its acceptance criteria in §30 are comparative:
"lower p95/p99", "faster or equal first useful coverage", "reduced obsolete
decode work". Without a baseline those cannot be evaluated, only asserted.
Implementing the perceptual-LOD work first would produce a change whose central
claim is unfalsifiable by construction.

## Corrections to the source prompt

1. §9 "cadence is tied to frame count". Cadence is `min(every 6th rendered
   frame, every 200 ms)`. A render-loop-independent heartbeat already exists at
   `Viewer.ts:1959`. What does NOT exist is an out-of-band tick on camera
   change, hierarchy arrival or commit: `_tickStreaming` has three references
   and none are event-driven. Hierarchy growth only invalidates the rescore
   cache through `store.size` in the signature (`StreamingScheduler.ts:1147`).
2. §3.1 proposes projected spacing in screen pixels. The existing
   `projectedSize` (`streamingScore.ts:88-90`) is `boxDiagonal / distance`:
   unitless, no FOV, no viewport term, saturating near 1. A pixel model is a
   genuine addition, but no current constant transfers to it.
3. §13 "memory governance is point-count based" is true for selection, eviction
   and the pressure loop; false for the compressed cache, the first-admission
   ceiling, PNTS decode and the metered upload pipe, which are already in bytes.
   There is no host-memory probe anywhere: no `performance.memory` read in src/.
4. §2 "create a benchmark harness". `src/perf/frameTelemetry.ts` already gives
   p50/p95/p99, over-16.7/33.3 counts and effectiveDpr;
   `benchmarks/performance/frameRecord.ts` already does p95 regression
   comparison; `streamingBenchmark.ts` already records firstPaint,
   timeToCoarseStable, timeToRefinedStable, thrashEvents and cache counters.
5. §17 "overlays reproject every rendered frame" is true, but all three overlays
   already bail on empty models, and probe is separately gated behind
   `pointerMoved()`.

Confirmed exactly as written: §4 (`DEPTH_WEIGHT = 1000` against
`SIZE_TERM_MAX = 999` makes ranking strictly lexicographic by depth) and §14
(`DPR_MOTION_FLOOR = 1.0` prevents any reduction on a DPR=1 panel).

## Phase 0 work

Bounded, changes no defaults, and every item is absent today.

1. Counters the baseline needs and the tree lacks: idle/skipped rAF frames
   (`noteSkipped` only advances a private field), DPR transitions
   (`_lastDprChangeMs` is internal and never reported), scheduler nodes-visited
   per pass, and cumulative request counts.
2. The immediate-versus-metered commit benchmark §11 asks for. It does not
   exist: `tests/benchmark/streamingNav.test.ts:440` runs only the default path
   and says so. No test, spec or script sets `streamingCommitMode=metered`.
3. The stickiness churn A/B §12 asks for. `tests/streamingEvictionChurn.test.ts`
   measures churn with stickiness OFF; nothing compares the two.

## Defects found while verifying, worth fixing regardless

- `devFlags.uploadQueue` defaults to `true` and is inert: parsed, reported,
  never read by a controller (`devFlags.ts:73-75`). Any reasoning from "the
  upload queue is on by default" is wrong; the live switch is
  `streamingCommitMode`, default `immediate`.
- `streamingBudget.ts:220-221` says the scheduler "does NOT yet pass a margin,
  so this is currently inert in production". False since `streamingAttach.ts:240`
  wired it.
- `makeStreamingCommit` never passes `maxItemBytes` (`meteredCommit.ts:190`), so
  the upload queue's only hard byte ceiling defaults to `POSITIVE_INFINITY`
  (`gpuUploadQueue.ts:192-195`). Every other limit is documented soft and may
  overshoot by one item.

## UX sections: what fits inside the ceiling

The entry chunk measures 805 KiB against 812. A fully lazy panel costs 0.5-2 KiB
of eager wiring; anything reachable before first paint or before a scan opens is
eager by contract and lands at 1-5 KiB, calibrated against the raise log in
`scripts/check-bundle-budget.mjs`. At most one or two such surfaces fit, and the
rolldown 1.2.3 pin already holds back 14 KiB.

- §19 Profile entry point: FEASIBLE. There is no Profile action in the command
  palette and no Profile button in the tool dock; a profile today takes four
  actions (arm measure, choose the Profile kind, click A, click B) and five to
  reach the docked workbench. An entry point mirrors existing patterns and costs
  about what the LayerGroupsPanel control did. Endpoints are ALREADY draggable
  in the 3D scene (`MeasureController.ts:1956-1963`); they are not draggable
  inside the workbench, which is the real §19 gap.
- §20 Contextual export: PARTIAL. The premise holds: `ProcessStudioPanel.ts`
  carries an `EXPORT_LOCATION` map precisely because "the panel that says a
  product exists is not the panel that exports it, and the path is three panels
  away", and Contour Studio is the only surface with a real permit gate. But a
  new always-present menu is eager. The smaller honest win is surfacing the
  existing permit where products are already listed.
- §18 Task launcher: NOT RECOMMENDED. Eager by contract, and Process Studio plus
  `workflowCardRender.ts` already render task-shaped status.
- §21 Information hierarchy: ALREADY DESIGNED. See
  `2026-09-10-scene-mode-design.md`, "design approved, not implemented", target
  v0.6.9. It covers the appearance-versus-data separation §21 asks for.
- §24 Accessibility: largely already satisfied. Severity is a rising bar plus
  the word (`issueSeverityStyle.ts:8-13`), glyph beside colour
  (`workflowCardRender.ts:34-39`), a forced-colors stylesheet, one app-wide
  polite region (`politeAnnounce.ts`), 44px touch targets, ARIA tabs in
  `MobileSheet.ts`. The recorded debt is the 11px type floor
  (`01-tokens.css:90-93`), a re-typing pass rather than a token edit.

## Not in scope

Sections 3-8 and 10 (perceptual LOD, hierarchical traversal, foveation,
prefetch, invalidation-driven rendering) are gated on Phase 0 by the prompt's
own sequencing and by §27's benchmark-gated promotion rule.
